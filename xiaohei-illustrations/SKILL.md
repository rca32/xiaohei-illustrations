# 샤오헤이 본문 일러스트

## 목적과 기본값

한국어 글을 위한 16:9 가로형 본문 그림을 만든다. 한 장에 하나의 판단, 흐름, 구조, 상태 또는 비유만 담는다. 복잡한 정보 도표, 발표 슬라이드, 상업용 포스터나 귀여운 마스코트 그림이 목적이 아니다.

샤오헤이는 검은 몸, 흰 점 눈, 가느다란 팔다리, 무표정한 얼굴을 가진 작은 캐릭터다. 장면의 핵심 행동을 직접 해야 한다. 캐릭터를 지워도 비유가 그대로 성립하면 행동을 다시 설계한다.

사용자와의 대화, 장면 계획, 그림 속 주석은 한국어가 기본이다. 사용자가 다른 언어를 명시하면 그 언어를 따른다. 기술 식별자나 사용자가 준 고유명사를 임의 번역하지 않는다.

## 필요한 참고만 읽기

- `references/style-dna.md`: 배경, 선, 색, 여백, 한글 표기.
- `references/xiaohei-ip.md`: 캐릭터 모양, 성격, 행동.
- `references/composition-patterns.md`: 구성 선택과 새로운 비유 만들기.
- `references/prompt-template.md`: 단일 이미지 생성·편집 프롬프트.
- `references/qa-checklist.md`: 생성 후 검수와 수정.
- `assets/examples/README.md`: 한국어 구성 예제 목록. SVG는 장면·표기 참고용이며 AI 생성 결과가 아니다. 최종 손그림 질감의 기준으로 삼지 않는다.

예제를 매번 전부 읽거나 이미지 모델에 기본 참조로 넣지 않는다. 사용자가 특정 예제를 지정했거나 구성을 확인할 필요가 있을 때만 해당 파일을 살펴본다.

## 1. 본문 이해

사용자가 준 본문, 파일, 링크 또는 스크린샷을 실제로 읽는다. 접근하지 못한 자료는 읽었다고 주장하지 않는다. 핵심 주장, 생각이 전환되는 지점, 그림으로 설명할 부분과 글로 남길 부분을 구분한다.

일정한 간격으로 그림을 배치하지 않는다. 정보 선별, 검증, 입력과 출력, 반복 개선, 맥락 인계, 우선순위처럼 독자의 이해를 바꾸는 지점을 고른다.

## 2. 장면 계획

계획만 요청한 경우 이미지를 생성하지 않는다. 일반적인 글은 4~8장, 짧은 글은 1~3장으로 시작하고 사용자가 지정한 장수를 우선한다. 장문도 이유 없이 9장을 넘기지 않는다.

각 장면에는 삽입 위치, 주제, 한 문장 핵심 생각, 구성 유형, 샤오헤이의 행동, 주요 물건, 정확한 한글 주석을 적는다. 주석은 보통 3~5개, 최대 8개이며 각각 짧은 단어 또는 어구로 쓴다. 원문에 없는 사실이나 숫자는 만들지 않는다.

## 3. 한 장씩 생성

생성을 요청받으면 불필요한 재확인을 거치지 말고 사용 가능한 이미지 생성 기능을 호출한다. 내장 `image_gen` 또는 이미지 만들기 기능이 제공되면 우선 사용한다. 구체적인 호출 방법은 현재 환경의 도구 지침을 따른다. 여러 장을 한 캔버스에 합치지 않는다.

이미지 생성 도구가 없으면 그 사실을 알리고 장면 계획과 바로 사용할 프롬프트를 제공한다. 코드로 만든 SVG나 PNG를 AI가 생성한 손그림처럼 대신 제출하지 않는다.

프롬프트에는 16:9, 순백색, 검은 손그림 선, 넓은 여백, 절제된 빨강·주황·파랑, 핵심 행동을 하는 샤오헤이, 허용할 정확한 한글 문구를 포함한다. 요청하지 않은 제목, 서명, 개인 브랜딩, 연락처, 홍보 문구, QR 코드를 금지한다.

추상 개념을 물리적 행동으로 바꾸고 단순한 물건 1~2개로 표현한다. 사용자가 명시하지 않은 한 예제의 구도와 물건을 그대로 복제하지 않는다.

## 4. 검수와 수정

`references/qa-checklist.md`를 적용한다. 배경, 여백, 비유, 캐릭터 행동, 한글 표기를 직접 확인한다. 주석의 철자, 띄어쓰기, 조사, 글자 잘림, 뜻을 바꾸는 오탈자를 살핀다.

문제가 적으면 해당 부분만 편집한다. 글자가 많이 틀렸다면 주석 수와 길이를 줄여 다시 생성한다. 한글이 어렵다는 이유로 임의의 중국어나 영문 주석으로 대체하지 않는다.

## 5. 저장과 전달

작업 공간이 있으면 최종 PNG를 다음 위치에 보관한다.

```text
assets/<article-slug>-illustrations/01-topic-name.png
assets/<article-slug>-illustrations/02-topic-name.png
```

원본 생성 파일을 보존한다. 사용자의 교체 요청이 없으면 기존 파일을 덮어쓰지 않는다. 결과가 다른 형식일 때는 실제 변환한 뒤 PNG로 안내하고 확장자만 바꾸지 않는다.

실제로 만든 장수, 각 그림의 쓰임, 실제 저장 위치, 미완료 사항만 짧게 전달한다. 파일을 만들지 않았거나 저장하지 못했다면 경로나 다운로드 링크를 지어내지 않는다.
